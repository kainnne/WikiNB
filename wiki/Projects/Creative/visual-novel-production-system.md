# 視覺小說模組化製作系統

這套 SOP 用來降低長篇視覺小說在多人或多 Agent 協作時的混亂。核心不是增加文件數量，而是讓每份文件只承擔一種責任，並把創作、實作和驗收分成清楚階段。

## 製作順序

1. 先確認作品目標、受眾、主題、範圍與不做事項。
2. 以中文完成世界觀、角色、幕次與場景規格。
3. 將選項、旗標、結局與回收條件整理成可檢查的分支設計。
4. 再進入 Ren’Py 腳本、UI 與資產整合。
5. 最後進行全路線 QA、資產授權檢查與在地化。

## 為什麼要拆分

若把所有規格寫進單一巨型文件，Agent 每次都要重新讀取大量無關內容，也容易同時修改劇情事實、程式規則與素材表。路由式文件讓任務只載入必要上下文，並讓變更可以回到正確的來源文件。

## 驗收觀念

「程式能啟動」只代表基本健康檢查通過。完整驗收還包含每個選項可達、旗標不互相污染、所有結局可解鎖、存讀檔正常、缺圖缺音可被偵測，以及實際使用的素材都有授權紀錄。
