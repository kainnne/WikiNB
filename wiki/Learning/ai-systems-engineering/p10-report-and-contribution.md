# P10 完整報告與貢獻任務

最後的報告要讓人知道系統解決什麼問題，以及為什麼相信它做得到。列滿技術名稱很容易，指出實際責任、證據與限制比較有價值。

先選一個使用情境，沿「輸入→資料→處理→工具→權限→結果」完整解釋。接著說明出錯、斷網與重啟怎麼處理。對於不確定的部分，寫成待確認問題，不把合理猜測混成專案現況。

## 選一個可驗收的貢獻

可以是明確的 API 契約、權限測試、錯誤回傳改善、可重現部署或量測報告。範圍不必大，但要有起點、改動、正常案例、失敗案例與可回復方式。

如果要談導入價值，回到使用者的實際流程：原本怎麼做、改動省掉哪一步、誰維護、錯誤如何交回人處理。仍待市場或現場驗證的價值，就保留為假設，不寫成已達成效益。

## 練習

做一次 5–10 分鐘的完整流程解說，準備最新架構圖、待確認問題和一個小型成果。讓聽者挑一個錯誤情境，現場追它會在哪裡被處理。

自我檢查：能用程式、配置、事件與量測支持主張；若只記得產品介紹，回到對應單元補資料流與證據。
