# N14 自己建立完整 Agent

完整 Agent 不以元件數量驗收。使用者能完成哪件事、資料從哪裡來、誰有權改、失敗後怎麼處理，才是整合的重點。

用前面的設備助手接四條能力：查狀態、讀維護規則、提出修改、等待真人核准。一般使用者可以查授權範圍內的資料；修改先留下提議，再由符合資格的人確認。執行後保存實際結果，不只保存模型說了什麼。

## 做出能重現的小系統

先寫需求與契約，再接執行迴圈、狀態、權限和測試。資料可先用 SQLite，依確實需要的並行、交易或部署條件再考慮 PostgreSQL；不是把資料庫名稱換掉就算深化。

從乾淨的啟動步驟開始，讓另一個用戶端完成一次查詢與一次提議。重啟後確認紀錄仍在，未核准的提議沒有被偷偷執行。框架只能表達流程，不能代替你決定正確的授權與業務規則。

## 練習

交一條正常路徑和至少三條失敗路徑：例如缺資料、越權、工具失敗。每條都附輸入、事件紀錄、回應和實際資料變化。

再選一處關鍵程式，在 AI 協助下自行修改，預測結果後測一次。能執行整包程式與能理解自己的改動，是不同能力。

自我檢查：另一個人能依你的說明啟動並驗證系統，你能指出每個重要動作的資料來源、權限與執行位置。
